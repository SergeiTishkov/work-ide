# Каталог блоков: источники и инструменты

Из чего собирается идентичность. Читать при заполнении вопросника (§13) и при
пересмотре набора источников.

Технические детали каждого источника — в `config/sources.catalog.yaml`.
Включение и параметры — в `identities/<префикс>/<префикс>_sources.yaml`.

## Источники вакансий

Все замеры — за один прогон, 2026-07-30/31. Цифры зависят от профиля: «полезный
выход» ниже считался для .NET-разработчика, ищущего удалённую работу.

### Площадки только с удалённой работой

Помечены `remote_only: true` в каталоге. Флаг важен для скоринга: сам факт
публикации на такой площадке служит подтверждением удалёнки, иначе гейт
«не подтверждено как remote» давал бы массовые ложноотрицательные.

| Источник | Объём | Сильные стороны | Слабые стороны |
|---|---|---|---|
| **weworkremotely** | ~242 | Лучший сигнал/шум. Структурное поле `region` — самый надёжный гео-сигнал. Англоязычные | Воронку отклика держит у себя: в 71% вакансий «To apply» ведёт обратно на WWR. Фетчер вытаскивает сайт компании из блока «Headquarters/URL» |
| **remoteok** | ~100 | Большой поток, только remote | Зашумлён: попадается контент, вообще не являющийся вакансией. Отдаёт только последние ~100, глубины по времени нет |
| **jobicy** | ~100 | Структурированная зарплата и гео | Фильтр `industry=dev` обязателен, иначе много не-IT |
| **remotive** | ~35 | Явное поле `candidate_required_location` | Мало. Параметры `limit`/`search` на практике игнорируются |
| **himalayas** | ~20 | `locationRestrictions` — самый явный гео-сигнал из всех | Очень мало, отдаёт ~20 независимо от `limit` |

### Прямо от работодателей

| Источник | Объём | Комментарий |
|---|---|---|
| **ats** | зависит от списка | Официальные публичные API систем найма (Greenhouse, Lever, Ashby, Recruitee) — те, на которых работают виджеты вакансий на сайтах компаний. Без посредника, без чужой воронки отклика. Замер: Stripe 546, Cloudflare 284, GitLab 185, Notion 111 |

**Главный рычаг качества здесь — список компаний**, а не сам источник. В
`<префикс>_ats_targets.yaml` нужно класть работодателей, релевантных вашему
профилю. Стартовый список из технологических компаний дал 1526 вакансий и ноль
кандидатов для .NET-профиля: механизм работал, список был не тот.

Где брать кандидатов: компании с высокими legacy/enterprise-сигналами из
`data/<префикс>/knowledge/<префикс>_companies.json`, либо поиском по отрасли.
Проверить токен доски можно одним запросом:
`curl https://boards-api.greenhouse.io/v1/boards/<токен>/jobs`

### Нишевые

| Источник | Объём | Комментарий |
|---|---|---|
| **hn_whoishiring** | ~22 | Ежемесячный тред Hacker News. Легаси и enterprise-вакансии часто попадают сюда, а не на джоб-борды; иногда встречаются «тихие» позиции без конкуренции. Формат вольный, компания и локация парсятся эвристически. Ключевые слова — параметр, каждое стоит одного HTTP-запроса |
| **arbeitnow** | ~175 | **По факту немецкий рынок.** Давал 68% базы при ~6% полезного выхода: большинство вакансий немецкоязычные и отсеиваются языковым фильтром. В шаблоне выключен по умолчанию; включать, если читаете по-немецки |
| **manual** | сколько занесёте | Не автоматический. Находки агента с площадок, которые нельзя читать программно (LinkedIn, Indeed, Glassdoor — 403 за анти-бот защитой), заносятся через `tools/ingest_manual.py`. Для узких профилей часто самый ценный канал: публичные борды слабо покрывают редкие комбинации требований |

## Инструменты

| Инструмент | Что делает | Когда нужен |
|---|---|---|
| `pipeline.py` | Полный цикл: сбор → нормализация → скоринг → дедупликация → проверка ссылок → отчёт | Основная команда каждого прогона |
| `doctor.py` | Самопроверка: идентичность, зависимости, конфиги, доступность источников | После клонирования и когда что-то странно |
| `identity.py` | Список, валидация, разрешение идентичности, сравнение с шаблоном | Онбординг и диагностика |
| `kb.py` | База знаний: статусы, заметки, оценки зарплаты и репутации | Ручная работа с находками |
| `ingest_manual.py` | Занести находки, полученные веб-поиском | После ручного этапа RUNBOOK |
| `company_intel.py` | Возраст и размер компании из Wikidata | Периодически, для зрелости компаний |
| `link_check.py` | Проверка живости ссылок | Автоматически внутри пайплайна |
| `report.py` | Пересобрать отчёт без нового сбора | После правки критериев |
| `migrate_to_identity.py` | Перенос старой раскладки в идентичность | Одноразово, историческое |

## Ручные обогащения базы

Не автоматизируются принципиально — источники за анти-бот защитой, обходить
которую проект не будет (см. Большую Конституцию). Собирает агент обычным
веб-поиском, как это делал бы человек.

```bash
# репутация работодателя (Glassdoor и т.п.)
python tools/kb.py set-company-reputation --identity <p> --company "Acme" \
    --rating 4.2 --wlb 4.4 --source "Glassdoor" --retrieval web_search --reviews 257

# вилка зарплаты, если в вакансии её нет
python tools/kb.py set-salary-estimate --identity <p> --id <vacancy-id> \
    --low 60000 --high 80000 --period year --source "Glassdoor"

# статус после отклика
python tools/kb.py set-status --identity <p> --id <vacancy-id> --status applied --notes "..."
```

Про `--retrieval`: `web_search` означает «цифры из поисковой выдачи,
первоисточник не открывался». Это данные второй руки, и отчёт честно об этом
пишет. Перед реальным откликом стоит открыть первоисточник глазами.

## Как выбирать набор

Больше источников — не всегда лучше. Источник с низким выходом для вашего
профиля каждый прогон засоряет базу мусором, который придётся отсеивать
фильтрами, а каждый новый фильтр — риск отсечь лишнее.

Разумная последовательность: включить все `remote_only` площадки, добавить `ats`
и наполнять список компаний под себя, `manual` держать включённым всегда. Узкие
источники подключать осознанно, померив выход через пару прогонов
(`python tools/kb.py stats` и раздел «Здоровье источников» в отчёте).
